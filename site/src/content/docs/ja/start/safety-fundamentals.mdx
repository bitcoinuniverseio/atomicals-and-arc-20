Atomicals における損失の多くは攻撃ではありません。通常のウォレットがするのと同じように、色付きの
出力を使ってしまった、ごく普通の Bitcoin トランザクションです。

## 決してしないこと

- シードフレーズ、秘密鍵、ウォレットのエクスポートファイルを、私たちを含め何者にも渡さないで
  ください。正当な検証にそれらは必要ありません。
- 色付きの出力を含む集合から、汎用の Bitcoin ウォレットに手数料用の入力を選ばせないでください。
- ティッカー、画像、名前、マーケットプレイスの出品を、誰かが何かを作った証拠として扱わないで
  ください。
- インデクサの応答を最終的な真実として扱わないでください。それはある時点における、あるバージョンの
  見解です。

## 署名前の八つの確認

<Steps>

1. **どの出力が色付きか。** 資産を保持する正確なアウトポイントを特定します。ウォレットが答えられ
   ないなら中止してください。
2. **入力の順序は何か。** 割り当ては入力と出力を順に処理します。順序が結果を変えます。
3. **各出力はサトシでいくらか。** トークンの単位ではありません。サトシです。
4. **出力の順序は何か。** 出力ゼロは、発行と大半の送付の形において特別です。
5. **どこにどれだけ着地するか。** 署名前に、各出力の想定単位数が分かっている必要があります。
6. **何が焼失するか。** 置けない価値があれば破棄されます。意図がない限りゼロであるべきです。
7. **手数料はどこから出るか。** 色付きではなく、独立したカーディナル入力からです。
8. **ウォレットの確認画面は実際に何と書いているか。** 期待と一行ずつ比較してください。

</Steps>

<Aside type="danger" title="最も高くつく間違い">
色付きの出力を取引所の入金アドレス、通常の Bitcoin ウォレット、あるいは Atomicals を理解しない
サービスに送ると、その価値は通常のビットコインとして使われます。単位は失われます。回復の手段は
ありません。
</Aside>

## 焼失はどう見えるか

<BurnDiagram />

焼失はエラーではありません。Bitcoin トランザクションは有効で、採掘され、確認されています。単位に
行き場がないだけであり、バリデータはそれを破棄として記録します。正確なルールは
[焼失](/protocol/arc20/burns/) を、実務的な手順は
[焼失を避ける](/guides/avoid-burns/) を参照してください。

## 何も証明しない四つの主張

| 主張 | 実際に証明されること |
| --- | --- |
| ティッカーが一致する | ある Atomical に名前が割り当てられたこと。誰かについては何も。 |
| メタデータにそう書いてある | 誰かがペイロードに任意のデータを書いたこと。 |
| マーケットプレイスに出ている | 誰かが出品を送信したこと。所有権は決済時に別途検証されます。 |
| インデクサが残高を表示している | ある実装が、ある世代でそう考えていること。バージョンと鮮度を確認してください。 |

## ブロードキャスト後

1. Bitcoin 上の確認を待ちます。
2. インデックスがその高さに達し、安定した世代を報告するまで待ちます。
3. 資産の所在を読み直し、意図した出力と一致することを確認します。
4. トランザクションに記録された焼失を確認します。

確認とインデックス化は別の答えです。
[確認と再編成](/guides/confirmations-and-reorgs/) を参照してください。

## すでに問題が起きている場合

- ブロードキャスト前に拒否されたトランザクションは回復できます。
  [拒否からの回復](/guides/recover-from-a-rejection/)。
- 署名しないウォレットは通常、機能または符号化の問題です。
  [ウォレットの署名失敗](/guides/wallet-signing-failures/)。
- 残高がゼロに見えるのは、多くの場合インデックスが利用できないだけで損失ではありません。
  [インデックス利用不可と残高ゼロ](/guides/unavailable-indexer-vs-empty-balance/)。
- 確認済みの焼失は取り消せません。このサイトの何もそれを変えられません。
