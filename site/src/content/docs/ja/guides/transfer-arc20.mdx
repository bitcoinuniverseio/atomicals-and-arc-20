## 始める前に

- 対応ネットワーク: mainnet。
- 状態: プロトコルの挙動。
- 金額欄ではなく、アウトポイントとサトシ額で動作するウォレットまたはビルダーが必要です。

<Aside type="danger" title="リスクはすべて出力の大きさにあります">
大きさはサトシであり、トークンの金額欄ではありません。一つ間違えると残りが焼失します。
</Aside>

## うまくいく構成

| 位置 | 内容 |
| --- | --- |
| 入力 0 | 色付きロット |
| 入力 1 以降 | 手数料用のカーディナル入力 |
| 出力 0 | 受取人。送付する単位数に正確に合わせます |
| 出力 1 | 色付きのおつり。残りに正確に合わせます |
| 出力 2 | カーディナルのおつり（ある場合） |

## 手順

<Steps>

1. 色付きアウトポイントを一覧し、使用するロットを選びます。
2. 送付額を決めます。その数値は出力 0 のサトシ額でもあります。
3. 残りを計算します。ロットの額から送付額を引いたものが、出力 1 のサトシ額です。
4. 入力と出力の正確な組み合わせを
   [割り当てビジュアライザ](/tools/allocation-visualizer/) でモデル化します。
5. 焼失量がゼロであることを確認します。
6. 手数料用のカーディナル入力と、末尾にカーディナルのおつり出力を追加します。
7. 手数料の入力と出力を含めて再度モデル化します。焼失量はゼロのままでなければなりません。
8. 入力と出力の順序を保ったままトランザクションを組み立てます。
9. ウォレットの確認画面を、モデルと一行ずつ比較します。
10. 署名してブロードキャストします。

</Steps>

## 手順 7 が存在する理由

手数料の入力やおつり出力を加えると出力の集合が変わり、割り当ては出力を順に処理します。ウォレットが
おつりを追加する前には健全だった送付が、追加後に焼失することがあります。

## 費用

Bitcoin の手数料を、カーディナル入力から支払います。通常の送付には commit と reveal の組も探索も
不要です。

## 失敗した場合

- 出力額をサトシで指定できないウォレット: 別のビルダーを使ってください。
- 出力を並べ替えるウォレット: 別のビルダーを使ってください。順序は意味を持ちます。
- 焼失量がゼロでない: 出力の大きさを変更し、そのまま進めないでください。

## ブロードキャスト後

確認し、インデックス化を待ち、資産の所在を読み、記録された焼失量を確認します。
[トランザクションを検証する](/guides/verify-a-transaction/) を参照してください。
