Atomicals 中的多數損失並非漏洞利用，而是一般的比特幣交易，用一般錢包的方式花掉了一個著色輸出。

## 絕對不要做的事

- 絕不要把助記詞、私鑰或錢包匯出檔案交給任何對象，包括我們。任何正當的驗證都不需要它們。
- 絕不要讓通用比特幣錢包，從包含你著色輸出的集合中挑選手續費輸入。
- 絕不要把代號、圖片、名稱或市集掛單當成誰建立了某項事物的證明。
- 絕不要把索引器的回應當成最終真相。那是某個版本在某一時刻的看法。

## 簽署前的八項檢查

<Steps>

1. **哪些輸出是著色的。** 找出承載資產的確切 outpoint。如果錢包無法告訴你，就停下。
2. **輸入的順序為何。** 配置會依序走訪輸入與輸出，順序會改變結果。
3. **每個輸出以聰計是多少。** 不是代幣單位，是聰。
4. **輸出的順序為何。** 對於鑄造以及多數轉移型態，第零個輸出是特殊的。
5. **多少落到哪裡。** 簽署前，每個輸出都應有一個預期的單位數。
6. **什麼會被銷毀。** 如果有價值無法放置，它會被銷毀。除非你刻意如此，否則應當為零。
7. **手續費從哪裡來。** 來自獨立的基數輸入，絕不來自著色輸入。
8. **錢包提示實際寫了什麼。** 與你的預期逐行比對。

</Steps>

<Aside type="danger" title="代價最高的錯誤">
把著色輸出傳送到交易所入金地址、一般比特幣錢包，或任何不理解 Atomicals 的服務，代表這份價值會被
當成一般比特幣花掉。單位就此消失，沒有任何復原途徑。
</Aside>

## 銷毀是什麼樣子

<BurnDiagram />

銷毀不是錯誤。比特幣交易有效、被打包並確認。只是這些單位無處可去，於是驗證器把它們記錄為已銷毀。
確切規則見[銷毀](/protocol/arc20/burns/)，實際操作步驟見
[避免銷毀](/guides/avoid-burns/)。

## 四種什麼都證明不了的說法

| 說法 | 它實際證明了什麼 |
| --- | --- |
| 代號一致 | 某個 Atomical 被配發了一個名稱。關於是誰，什麼都沒說明。 |
| 中繼資料這樣寫 | 有人在 payload 中寫入了任意資料。 |
| 它在市集上掛單 | 有人送出了一筆掛單。所有權在結算時另行驗證。 |
| 索引器顯示有餘額 | 某個實作在某個世代這樣認為。請檢查版本與新鮮度。 |

## 廣播之後

1. 等待比特幣確認。
2. 等待索引到達該高度並回報一個穩定的世代。
3. 重新讀取資產位置，確認與你預期的輸出一致。
4. 檢查交易中記錄的銷毀。

確認與索引是兩個不同的答案。
參見[確認與重組](/guides/confirmations-and-reorgs/)。

## 如果已經出錯

- 在廣播前被拒絕的交易是可以挽回的：
  [從拒絕中復原](/guides/recover-from-a-rejection/)。
- 錢包不肯簽章，通常是能力或編碼問題：
  [錢包簽章失敗](/guides/wallet-signing-failures/)。
- 餘額顯示為零，往往是索引無法使用而不是損失：
  [索引無法使用還是餘額為空](/guides/unavailable-indexer-vs-empty-balance/)。
- 已確認的銷毀無法撤銷。本站的任何內容都改變不了這一點。
