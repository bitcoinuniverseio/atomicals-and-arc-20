## 核心

**Atomical**
: 由一笔比特币交易创建、并由一个比特币输出承载的数字对象。

**Atomical ID**
: Atomical 的持久身份，写作 `<txid>i<输出索引>`。只分配一次，永不改变。

**Atomical 编号**
: 按铸造顺序分配的序号。便于展示，但不是应当保存的身份。

**位置**
: 当前承载某个 Atomical 的未花费输出。每次移动都会改变。

**信封**
: reveal 交易见证中承载 `atom`、操作与 CBOR payload 的脚本结构。

**操作**
: 信封内的短代码，告诉验证器该做什么。例如：`ft`、`dft`、`dmt`、`nft`、`mod`、`sl`。

**commit 与 reveal**
: 两笔交易的模式。commit 支付到一个 Taproot 输出，reveal 花费它并展示信封。

**Bitwork**
: 对交易 ID 的类工作量证明前缀要求，用于限制铸造与申领。

**候选**
: 对全局分配名称或代号的待定申领，此时规则尚未决出胜出者。

**已验证胜出者**
: 被规则判定为持有某个名称或代号的 Atomical。

**世代**
: 索引在链上某个一致位置的不可变快照。

**重组**
: 可能使先前已索引结果失效的比特币链重组。

## ARC-20

**ARC-20**
: Atomicals 的同质代币模型。一个单位等于一个着色聪。

**代号**
: 全局分配的 ARC-20 名称。不是创建者身份的证明。

**着色 UTXO**
: 被验证器认定为承载 ARC-20 价值的比特币输出。

**基数 UTXO**
: 不含 Atomicals 价值的普通比特币输出，用于手续费与找零。

**直接 FT**
: 一步式 `ft` 铸造，把全部供应量放入第零个输出。

**DFT**
: 通过 `dft` 创建的去中心化同质代币部署。

**DMT 申领**
: 使用 `dmt` 操作，针对某个 DFT 部署的一次铸造。

**永续 DFT**
: 受激活条件约束的去中心化模式，Bitwork 递进，并可选设置全局上限。

**铸造量**
: 每次有效的 DMT 申领放入第零个输出的确切聪面值。

**最大铸造次数**
: 固定模式部署所允许的有效申领次数。

**分配**
: 验证器关于哪个输出获得多少着色价值的判定。

**普通分配**
: 当没有操作 payload 改变它时的默认着色行为。

**销毁**
: 无法放入任何可用输出、因而被销毁的着色价值。

**拆分**
: `y` 操作，在一个输出上分离同质价值。

**自定义着色**
: 受激活条件约束的 `z` 操作，显式分配着色价值。

**splat**
: 非同质分支上的 `x` 操作，用于分离位于同一输出上的多个 Atomicals。

**无通胀校验**
: 着色输出总额不得超过着色输入总额的规则。

## 名称与集合

**Container**
: 具名的集合身份，条目可以证明其归属。

**DMINT**
: 针对已封存清单的 Container 条目去中心化铸造。

**封存**
: 使某个 Atomical 或 Container 清单永久不可更改。

**Realm**
: 以 NFT 形式持有的顶级 Atomicals 名称。

**Subrealm**
: 依据父级 Realm 规则申领的子名称。

**Payname**
: 用作收款目标的 Realm。

**IDNA**
: 比较与归一化名称时使用的国际化域名规则。

**易混淆名称**
: 两个不同的名称，显示得足够相似以致可能误导读者。

## 集成

**游标**
: 不透明且经过签名的分页令牌，指向某个世代内的稳定位置。

**就绪**
: 服务此刻能否给出正确回答。这与已配置或正在运行是不同的概念。

**新鲜度**
: 索引相对链尖落后多少。

**幂等键**
: 由客户端提供的键，使重试变更操作变得安全。

**请求标识**
: 在响应与日志中返回的每次请求标识，用于追踪一次调用。

**PSBT**
: 部分签名的比特币交易，是服务与钱包之间的交换格式。

**BIP-322**
: 本站用于在不移动资金的情况下证明对某地址控制权的消息签名方案。

**SIGHASH**
: 决定签名承诺覆盖交易哪些部分的标志。
