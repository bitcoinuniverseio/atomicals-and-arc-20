## 核心

**Atomical**
: 由一筆比特幣交易建立、並由一個比特幣輸出承載的數位物件。

**Atomical ID**
: Atomical 的長久身分，寫作 `<txid>i<輸出索引>`。只配發一次，永不改變。

**Atomical 編號**
: 依鑄造順序配發的序號。便於顯示，但不是應當保存的身分。

**位置**
: 目前承載某個 Atomical 的未花費輸出。每次移動都會改變。

**信封**
: reveal 交易見證中承載 `atom`、操作與 CBOR payload 的指令碼結構。

**操作**
: 信封內的短代碼，告訴驗證器該做什麼。例如：`ft`、`dft`、`dmt`、`nft`、`mod`、`sl`。

**commit 與 reveal**
: 兩筆交易的模式。commit 支付到一個 Taproot 輸出，reveal 花費它並揭露信封。

**Bitwork**
: 對交易 ID 的類工作量證明前綴要求，用於限制鑄造與申領。

**候選**
: 對全域配發名稱或代號的待定申領，此時規則尚未決出勝出者。

**已驗證勝出者**
: 被規則判定為持有某個名稱或代號的 Atomical。

**世代**
: 索引在鏈上某個一致位置的不可變快照。

**重組**
: 可能使先前已索引結果失效的比特幣鏈重組。

## ARC-20

**ARC-20**
: Atomicals 的同質代幣模型。一個單位等於一個著色聰。

**代號**
: 全域配發的 ARC-20 名稱。不是建立者身分的證明。

**著色 UTXO**
: 被驗證器認定為承載 ARC-20 價值的比特幣輸出。

**基數 UTXO**
: 不含 Atomicals 價值的一般比特幣輸出，用於手續費與找零。

**直接 FT**
: 一步式 `ft` 鑄造，把全部供應量放入第零個輸出。

**DFT**
: 透過 `dft` 建立的去中心化同質代幣部署。

**DMT 申領**
: 使用 `dmt` 操作，針對某個 DFT 部署的一次鑄造。

**永續 DFT**
: 受啟用條件約束的去中心化模式，Bitwork 遞進，並可選設定全域上限。

**鑄造量**
: 每次有效的 DMT 申領放入第零個輸出的確切聰面額。

**最大鑄造次數**
: 固定模式部署所允許的有效申領次數。

**配置**
: 驗證器關於哪個輸出取得多少著色價值的判定。

**一般配置**
: 當沒有操作 payload 改變它時的預設著色行為。

**銷毀**
: 無法放入任何可用輸出、因而被銷毀的著色價值。

**拆分**
: `y` 操作，在一個輸出上分離同質價值。

**自訂著色**
: 受啟用條件約束的 `z` 操作，明確配置著色價值。

**splat**
: 非同質分支上的 `x` 操作，用於分離位於同一輸出上的多個 Atomicals。

**無通膨檢查**
: 著色輸出總額不得超過著色輸入總額的規則。

## 名稱與集合

**Container**
: 具名的集合身分，項目可以證明其歸屬。

**DMINT**
: 針對已封存清單的 Container 項目去中心化鑄造。

**封存**
: 使某個 Atomical 或 Container 清單永久不可變更。

**Realm**
: 以 NFT 形式持有的頂層 Atomicals 名稱。

**Subrealm**
: 依父層 Realm 規則申領的子名稱。

**Payname**
: 用作收款目標的 Realm。

**IDNA**
: 比較與正規化名稱時使用的國際化網域名稱規則。

**易混淆名稱**
: 兩個不同的名稱，顯示得足夠相似以致可能誤導讀者。

## 整合

**游標**
: 不透明且經過簽章的分頁權杖，指向某個世代內的穩定位置。

**就緒**
: 服務此刻能否給出正確回答。這與已設定或正在執行是不同的概念。

**新鮮度**
: 索引相對鏈頂落後多少。

**冪等鍵**
: 由用戶端提供的鍵，使重試變更操作變得安全。

**請求識別碼**
: 在回應與紀錄中回傳的每次請求識別碼，用於追蹤一次呼叫。

**PSBT**
: 部分簽章的比特幣交易，是服務與錢包之間的交換格式。

**BIP-322**
: 本站用於在不移動資金的情況下，證明對某地址控制權的訊息簽章方案。

**SIGHASH**
: 決定簽章承諾涵蓋交易哪些部分的旗標。
